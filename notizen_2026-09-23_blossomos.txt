--------------------------------------------------------------
1. RECHERCHE – Aufbau der Webseite
--------------------------------------------------------------

- https://blossom.computer/downloads ist eine SvelteKit-Single-
  Page-App (Pfade unter /_app/immutable/..., eigenes Stylesheet
  "download-card.Bcd_7A2j.css").
- Die Seite bietet BlossomOS (Linux-Distribution) in Editionen:
    Online   - "A small ISO that downloads BlossomOS during
               installation. Recommended for most people."
               Badge: "All GPUs", "Recommended"
    Offline  - "The whole system is inside the ISO."
               Varianten: Standard (AMD/Intel), NVIDIA Open,
               NVIDIA Legacy
- Im Server-HTML stehen KEINE Download-Links und KEINE Versions-
  nummer: die Karten zeigen nur Lade-Platzhalter
  (CSS-Klasse "loading-glare"), die Daten kommen clientseitig.
- SvelteKit-Datenendpunkt /downloads/__data.json liefert nur
  {"type":"data","nodes":[null,null]} - keine serverseitigen Daten.
- /api/downloads existiert nicht (404).
- Im HTML eingebettet ist ein verstecktes Formular:
      <form method="POST" action="/api/downloads/verify">
        <input type="hidden" name="cf-turnstile-response"/>
        <input type="hidden" name="iso"/>
      </form>
  -> Der eigentliche Download ist mit Cloudflare Turnstile
     (Bot-Schutz) gesichert; ohne geloestes Captcha kein Download
     ueber die Webseite.
- Kuriositaet: die Seite enthaelt <audio src="/novideo.mp3">
  (Easter Egg) und Posthog-Analytics im JS-Bundle.

3. ERKENNTNIS – isodata.json = perfektes Ueberwachungsziel
--------------------------------------------------------------

GET https://cdn.blossomos.org/iso/isodata.json liefert (128 Byte):

    {
      "name": "BlossomOS-2026.09.18-x86_64.iso",
      "sha256": "13d19534fbeca567e004d84de9c6d4b7af2e9a086959b46c357cc55b87f983b5"
    }

- Enthaelt Dateiname UND SHA256 der aktuellen Online-ISO.
- Versionsschema ist datumsbasiert: YYYY.MM.DD (Rolling-Release-
  Art; "always the latest build" laut Webseite).
- Aenderung der Datei = neues Release -> ideal als Check-URL.

--------------------------------------------------------------
4. ERKENNTNIS – ISO liegt offen am CDN (Turnstile umgangen)
--------------------------------------------------------------

HEAD https://cdn.blossomos.org/iso/BlossomOS-2026.09.18-x86_64.iso
  -> 200 OK, Content-Type: application/octet-stream,
     Content-Length: 8425750528 (~8,4 GB!),
     Last-Modified: Fri, 18 Sep 2026 14:18:11 GMT,
     Server: cloudflare, cf-cache-status: DYNAMIC
- Die ISO ist trotz "small ISO"-Werbung 8,4 GB gross (enthaelt das
  Basissystem; nur der Rest wird bei der Installation nachgeladen).
- Turnstile schuetzt nur den Website-Button, nicht die CDN-Datei.
- Verzeichnislisting https://cdn.blossomos.org/iso/ -> 200, aber
  leer (0 Byte); keine Liste alter ISOs oeffentlich.

5. IMPLEMENTIERUNG
--------------------------------------------------------------

Neue Datei: sites/blossomos.py

    NAME  = "BlossomOS Online"
    URL   = "https://cdn.blossomos.org/iso/isodata.json"
    SLUG  = "blossomos"
    NOTES = "Download: https://blossom.computer/downloads
             (Online-Edition)"

  - extract(text): parst das JSON, Version aus dem Dateinamen via
    Regex BlossomOS-(\d{4}\.\d{2}\.\d{2})-x86_64\.iso
    -> "2026.09.18"
  - extract_history(text): die Version IST das Datum
    (2026.09.18 -> 2026-09-18), also echte Release-Daten ohne
    Zusatzquelle. Keine oeffentliche Release-Liste -> die Historie
    waechst mit jedem erkannten Release.
  - Kein Changelog: BlossomOS publiziert keins.
  - DOWNLOADS:
      1) "https://cdn.blossomos.org/iso/
          BlossomOS-{version}-x86_64.iso"          (die ISO)
      2) {"url": ".../isodata.json",
          "filename": "BlossomOS-{version}-x86_64.isodata.json"}
          (versionierter Hash-Beleg zur ISO)

Core-Aenderung in newsbot.py:

  - "filename" in DOWNLOADS-Dicts unterstuetzt jetzt ebenfalls den
    {version}-Platzhalter (vorher nur in der URL):
        name = (filename or download_filename(url))
               .format(version=version)
  - __version__ = "1.12.0"

--------------------------------------------------------------
8. OFFENE PUNKTE / HINWEISE
--------------------------------------------------------------

- Jede neue BlossomOS-Version laedt erneut ~8,4 GB (Policy "alles
  behalten" -> alte ISOs bleiben liegen). Bei Platzmangel: die
  ISO-Zeile in DOWNLOADS auskommentieren; der isodata.json-Beleg
  dokumentiert die Version weiterhin.
- isodata.json enthaelt nur die Online-Edition; Offline-Varianten
  (Standard/NVIDIA) haben dort keine Metadaten und wuerden ein
  eigenes Vorgehen brauchen (aktuell nicht gewuenscht).
- Falls Blossom die CDN-Struktur aendert (anderer JSON-Schluessel
  oder Pfad), schlaegt extract() fehl und wird geloggt - kein
  stiller Fehlschlag.
